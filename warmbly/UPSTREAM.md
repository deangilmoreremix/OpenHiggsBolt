Modifications for this repo (theme only, via Warmbly's own accent mechanism):
- `web/src/styles/theme-brand.css` (new): accent scale generated by upstream `accentScale()`, plus dark surfaces.
- `web/src/global.css`: imports theme-brand.css. `web/index.html`: `data-accent`, dark by default, surface color.
- `web/src/lib/theme.ts`: only the dark browser-chrome color. Dark is the default through Warmbly's own `setDefaultTheme("dark", true)` call in `web/src/main.tsx` (upstream's `DEFAULT_THEME` and its tests are untouched).
- Removed the marketing/landing site (`site/`), except `site/public/{install.sh,cli.sh,cli.ps1}` and their `.sha256` files, which Makefile targets use. Removed the `make site` target. Everything else is unmodified upstream.
- No Warmbly sign-in. `web/src/lib/hostSession.ts` (new) loads the host app's Clerk session (`VITE_CLERK_PUBLISHABLE_KEY`, optional `VITE_HOST_SIGN_IN_URL`, default `/sign-in`) before the dashboard renders and stores the Clerk JWT as the dashboard's Token; a signed-out visitor is sent to the host's own sign-in. `refreshToken` asks Clerk instead of calling `/auth/refresh`. The login, register, reset-password, SSO pages and their hooks are deleted; `/auth`, `/auth/login`, `/auth/register` and `/auth/*` are redirect-only routes to the host sign-in. Onboarding (workspace setup after sign-in) is kept. Adds `@clerk/clerk-js` to `web/package.json`.
- The Warmbly backend is not wired yet: it must accept the Clerk JWT as its bearer token (or exchange it), and `VITE_API_URL` must point at it.
- Warmbly Studio (standalone studio tab at `/studio/warmbly`): `warmbly/web` builds to `public/warmbly-app/` via `pnpm build:warmbly` (`vite build --base=/warmbly-app/`, run by the Netlify build command), is shown by `src/apps/warmbly/WarmblyStudio.jsx` in an iframe, registered in `components/StandaloneShell.js` (tab, slug map, render) with `app/warmbly/page.tsx` redirecting to the studio, `/warmbly-app(.*)` protected in `middleware.js`, and Netlify SPA fallbacks for `/warmbly-app/*`. It shares the host's Clerk session (same origin). Web app changes for this: `router.tsx` basepath from `BASE_URL`, `vite.config.ts` font preload and `faviconBadge.ts` respect the base, `hostSession.ts` sends the whole host page to `/sign-in`. Override the frame address with `NEXT_PUBLIC_WARMBLY_URL`. `pnpm build:warmbly` passes `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` to the studio as `VITE_CLERK_PUBLISHABLE_KEY` when the latter is unset.
- When the Warmbly API is added: allow its origin in the `connect-src` of the CSP set in `middleware.js`, and set `VITE_API_URL` and `VITE_CLERK_PUBLISHABLE_KEY` for the `build:warmbly` step.
- Feature guides (the docs site, like docs.warmbly.com): `warmbly/docs` (Fumadocs, static export) builds to `public/warmbly-docs/` with ``pnpm build:warmbly-docs`` and is served from `/warmbly-docs/` (Netlify rule for `/warmbly-docs`; the build runs as part of the repo build and retries once). The studio's in-app links to `https://docs.warmbly.com/...` point at it through `VITE_DOCS_URL=/warmbly-docs` (`docsLinks` plugin in `web/vite.config.ts`). Docs changes, all env-driven (defaults are upstream's): `next.config.mjs` basePath from `DOCS_BASE_PATH`; `components/shared/provider.tsx` search index URL; `DOCS_SITE_URL` for `metadataBase`, sitemap and robots (set it in the deploy env for canonical URLs); `app/global.css` brand block. Guide screenshots are Warmbly's own images and keep its original colors.
- Docs are how-to guides only (no upgrade material): removed the `learn/`, `api/` and `development/` sections and the guides `warmbly-cloud`, `billing`, `partnership` and `ai-credits` from `warmbly/docs/content/docs/`, and in the other guides the lines, list items, table rows and sections about plans, trials, billing, allowances and Warmbly Cloud (a one-off scripted cleanup, so after updating upstream the same cleanup has to be repeated). Docs app: removed the section switcher and the header links to warmbly.com, app.warmbly.com and GitHub; the 404 page lists only Guides. The build sets `DOCS_SITE_URL` from the deploy's `URL`. The studio's in-app links to removed pages go to the guides home (`docsLinks` in `web/vite.config.ts`). The generated help guide (`scripts/build-warmbly-guide.mjs`) therefore has 52 features, with no cloud or billing wording.
- No upgrade or billing in the app: removed the Billing and Limits and Mailbox sign-in (Partnership plan) and Warmbly Cloud settings pages, the Agency billing page and the `/connect` page (routes, navigation and command-palette entries too); the header plan pill and balance meter, trial bar, balance banner and subscription gate; the upgrade dialog (`useUpgradeDialog` is kept as a no-op so callers compile), the locked-feature overlay (`LockedSurface` now only renders its children), the mailbox-allowance dialog (the allowance lookup is switched off), the Accounts pool-size/Warmbly Cloud banners and cloud card, the Placement "Warmbly Cloud panel" and the pay-from-balance blocks in the placement dialogs, the plan badges and upgrade click in the sidebar, the tour's Plans chapter (skipping now simply ends the tour), the Notifications "Billing" group, the Data export's "Billing history" group, and plan/billing wording in a few settings and agency copy. Tests for removed pieces were deleted or updated. Not removed: backend-provided billing and plan logic, metered agency AI-balance pieces that only render for a metered agency, and the Warmbly Cloud wiring that only appears for an instance already linked to it (redirects, sign-in through Cloud). A scan of every page in a self-hosted run shows no billing, upgrade or plan-pricing wording. After updating upstream this change has to be redone.
