---
name: think-before-coding
description: State assumptions explicitly, present multiple interpretations, push back when warranted
---

Before writing any code, follow this checklist:

1. **State assumptions explicitly** — What do you know? What are you assuming? What might be wrong?
2. **Present multiple interpretations** — Could the requirement be understood differently? What are the trade-offs?
3. **Push back when warranted** — If something seems wrong, incomplete, or potentially harmful, say so
4. **Stop when confused** — Ask for clarification rather than guessing

Use this skill when:
- Starting a new feature
- Encountering ambiguous requirements
- Feeling uncertain about implementation approach
- Something seems "off" about a request

This prevents costly mistakes and ensures alignment before coding begins.
