---
name: receiving-code-review
description: Verify code review feedback before implementing
---

When receiving code review feedback, apply technical rigor before making changes.

Process:
1. Read each suggestion carefully — understand the intent behind it
2. Verify the feedback — run commands, check docs, test hypotheses
3. Ask questions if unclear — don't implement without understanding
4. Consider trade-offs — every change has costs and benefits
5. Implement only verified suggestions — reject performative agreement

The reviewer wants quality, not compliance. Push back when feedback is technically unsound, but do so with evidence.
