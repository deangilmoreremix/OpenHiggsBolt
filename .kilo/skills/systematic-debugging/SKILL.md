Use this skill when encountering any bug, test failure, or unexpected behavior. Before proposing fixes, you MUST find root cause first.

Four phases of systematic debugging:
1. Root cause investigation — reproduce the issue, gather logs, trace execution
2. Pattern analysis — identify similar issues, check for known patterns
3. Hypothesis and testing — form hypotheses, write minimal reproduction cases
4. Implementation with single fixes — apply targeted fixes, verify with tests

This skill emphasizes investigative rigor over quick fixes. No speculative changes allowed until root cause is confirmed.
