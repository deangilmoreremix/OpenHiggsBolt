---
name: simplicity-first
description: Minimum code that solves the problem; no speculative abstractions
---

Write the minimum code that solves the problem. Avoid:
- Speculative abstractions — Don't guess at future needs
- Flexibility for impossible scenarios — Don't handle what won't happen
- Excessive error handling — Handle real errors, not theoretical ones
- Premature optimization — Make it work, then make it fast if needed

The code should be:
- As simple as possible to meet current requirements
- Easy to understand and modify
- Focused on the actual problem, not potential variants

When in doubt, leave code verbose rather than clever. Clear code is better than concise code.
