# Personalization API — Manual Smoke Test Runbook

## Prerequisites
- A valid MuAPI key with generation credits
- Local development environment running on `http://localhost:3000` or `http://localhost:3111`
- Browser with localStorage enabled

## Test A — Upload All Asset Types
1. Navigate to `/personalization-demo`
2. Open Settings (click "Open Settings" or use the app Settings modal)
3. Enter your MuAPI key and save
4. Wait for the modal to auto-open
5. Upload the following assets:
   - **Identity**: 3 photos of the same person
   - **Logo**: 1 PNG/SVG logo
   - **Products**: 3 product images
   - **Brand References**: 2 brand images
   - **First Frame**: 1 image
   - **Last Frame**: 1 image
   - **CTA Graphic**: 1 image
6. Verify each upload shows:
   - Preview thumbnail
   - "Ready" status
   - No blob: URLs in the network tab

**Expected**: All 7 asset types upload successfully and return durable HTTPS URLs.

## Test B — Prompt Personalization
1. Fill in client profile:
   - Business: ABC Roofing
   - Industry: Roofing
   - Location: Tampa, Florida
   - Product: Residential Roof Replacement
   - Offer: Free Roof Inspection
   - CTA Headline: Protect Your Home Today
   - Button: Book Your Inspection
   - Phone: 555-555-5555
   - Website: abcroofing.com
2. Click "Personalize Prompt"
3. Verify the personalized prompt contains:
   - Client business name
   - Location
   - Product/service
   - Offer
   - CTA headline
   - Phone/website
4. Verify the original prompt is unchanged
5. Edit the personalized prompt
6. Confirm the edited value persists

**Expected**: Prompt personalization succeeds, original prompt unchanged, edit persists.

## Test C — Image Generation
1. Select source: any image demo
2. Select mode: "Recreate For Client"
3. Keep assets minimal (1 identity, 1 logo)
4. Click Generate
5. Monitor the generation status:
   - Should show "Submitting generation..."
   - Should show polling status
   - Should show "Complete"
6. Verify the result:
   - Image displays correctly
   - Logo overlay is visible (if exact logo handling is enabled)
   - Download button works
   - URL is accessible via direct GET

**Expected**: Image generates successfully, post-processed URL is returned, download works.

## Test D — Video Generation
1. Select source: any video demo
2. Select mode: "Face Only"
3. Upload 1 identity image
4. Click Generate
5. Monitor generation:
   - Submit succeeds
   - Polling shows status changes
   - Final result URL is returned
6. Verify:
   - Video plays
   - Face is replaced (visual check)
   - URL is accessible

**Expected**: Video generates successfully, face swap is applied, result URL works.

## Test E — Exact Logo & CTA
1. Select mode: "Complete Personalization"
2. Upload identity, logo, product images
3. Enable "Exact Final Overlay" for logo
4. Enable "Exact End Card" for CTA
5. Fill in all CTA fields
6. Generate
7. Verify:
   - Logo appears in final image/video (bottom-right, not stretched)
   - End card contains exact business name, CTA headline, button text, offer, phone, website
   - Final URL is the post-processed URL (check network tab)
   - Shared Media entry uses the final URL

**Expected**: Exact logo and CTA are applied deterministically, not regenerated by AI.

## Test F — Post-Processing Failure & Retry
1. Generate with invalid watermark endpoint (simulate by disconnecting network during post-processing)
2. Verify:
   - Error state shows: "Branding could not be applied"
   - "Retry Branding" button is visible
   - "Download Unbranded Version" is available
   - Original generated URL is preserved
3. Reconnect network
4. Click "Retry Branding"
5. Verify:
   - Only post-processing re-runs (no new AI generation)
   - Final result is updated

**Expected**: Post-processing failures are handled gracefully, retry works without regenerating.

## Test G — Studio Handoff
1. Generate an image
2. Click "Edit in Image Studio"
3. Verify Image Studio receives:
   - Result image URL
   - Original image URL
   - Personalized prompt
   - Client ID
4. Generate a video
5. Click "Edit in Video Studio"
6. Verify Video Studio receives:
   - Result video URL
   - Original video URL
   - Identity asset IDs
   - Personalized prompt

**Expected**: Studio handoff passes correct data via localStorage/sessionStorage.

## Test H — Publish
1. Generate any media
2. Click "Publish"
3. Select a platform
4. Verify:
   - Media URL is accepted
   - Caption/prompt metadata is passed
   - Publish succeeds or shows clear error

**Expected**: Publish integration works with the final post-processed URL.

## Manual Verification Checklist
- [ ] All 7 asset types upload and return durable URLs
- [ ] Prompt personalization includes client-specific data
- [ ] Image generation succeeds
- [ ] Video generation succeeds
- [ ] Exact logo overlay appears in final media
- [ ] Exact CTA end card contains correct text
- [ ] Final result URL is post-processed URL
- [ ] Post-processing failure shows retry options
- [ ] Retry branding reuses original generated URL
- [ ] Image Studio handoff works
- [ ] Video Studio handoff works
- ] Publish uses final URL

## Known Limitations
- Real API smoke tests are blocked if no MuAPI key is available
- Playwright E2E tests require a running dev server; compilation may take 2-5 minutes on first run
- `verify:muapi` reports 36 model endpoint mismatches (documented in `docs/personalization-verify-muapi-drift.md`)
