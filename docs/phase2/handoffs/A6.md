### 2.3 Why "add" is wrong — four independent reasons

**R1 — it breaks the zero-network render property, and the existing test cannot see it.**
`@remotion/google-fonts` loads the font **at render time, in the browser**, from a hard-coded
`fonts.gstatic.com` URL (§1.5). `FontFace.load()` is a browser-internal network request — it is
**not** `window.fetch`, so `src/shared/personalization/__tests__/noNetworkDuringBrandRender.test.ts`
(which spies only on `fetch` / `XMLHttpRequest` / `WebSocket`) would **still pass** while the
render silently talks to Google. That is the worst failure mode: a green test over a broken
property. In addition:

- the `delayRender('Fetching Inter font …')` handle makes the web-renderer **block** on a network
  round-trip before it captures a frame;
- an offline / air-gapped export falls back to a system face → the exported typography is
  **non-deterministic** and differs from the preview;
- `lib/fonts.ts` requests **5 weights** (`400,500,600,700,800`) × 1 subset → 5 woff2 requests per
  design, repeated per design instance.

**R2 — Remotion version lockstep.** Every `@remotion/*` package must match `remotion` exactly.
Repo 3 pins `4.0.200`; the target is `4.0.499`. Pinning `4.0.200` is a hard mismatch. The
`4.0.499` builds exist (§1.4), so this reason alone is not decisive — it just forces the diff
above rather than upstream's versions.

**R3 — THE DECISIVE ONE: 0 of the 7 repo-3 designs is a transparent overlay.** Even with every
dependency installed, all 7 paint an opaque full-canvas stage (§1.10):

| design | root paint | turn-offable? |
|---|---|---|
| `LogoIntro` | `<AbsoluteFill style={{ backgroundColor }}>` (129) + `staticFile(logoSrc)` (162) | no, and it needs a served `public/logo.svg` |
| `LowerThirds` | `<StageBackground />` → `linear-gradient(120deg, palette.zinc100, palette.zinc200)` (57, 93) | **no — hard-coded literal, not a prop** |
| `KineticText` | `<AbsoluteFill style={{ backgroundColor }}>` (161) | prop, but a full-scene type composition, not a bounded overlay |
| `BarChartRace` | `<AbsoluteFill style={{ backgroundColor: palette.white }}>` (90) | **no — hard-coded white** |
| `LineChartDraw` | `<AbsoluteFill style={{ backgroundColor: palette.white }}>` (54) | **no — hard-coded white** |
| `CaptionedShort` | `background: linear-gradient(160deg, ${backgroundColor}, ${mix(backgroundColor, …)})` (117) | no — `mix()` needs a hex |
| `PromoTemplate` | `palette.white` / `palette.zinc50` / `palette.ink` (91, 155, 261, 348) | **no** |

This reason is **independent of the dependencies**: paying the 6-package cost and the render-time
network fetch would still yield **zero** new overlay designs.

**R4 — assets.** `LogoIntro` → `public/logo.svg` via `staticFile()`; `PromoTemplate` →
`public/screenshot-1.svg` + `public/screenshot-2.svg` via `staticFile()`; `CaptionedShort` →
`public/captions.sample.json` imported at build time (§1.10). The browser web-renderer would have
to **serve** those files — more network traffic inside the "no network" render.

### 2.4 Quantified deferral

- **7 of 138** upstream templates (5.1 %) deferred.
- **0** of them would have been usable as an overlay.
- **6 new npm packages** + a render-time network fetch avoided.
- Deferred, not cancelled. **Re-open when** (a) A10's `templates/designs/fonts.ts` provides a
  **local** (bundled / base64) font so no runtime fetch is needed, and (b) the product can serve a
  `public/` directory to the web-renderer.

`docs/REMOTION_TEMPLATE_INVENTORY.md` §3 marks `wave-text` and `scramble-text` as
*"yes — background is a plain colour prop (set 'transparent')"*. **That is wrong.** Both use the
background colour as an argument to a **hex-parsing helper**, and the literal `"transparent"`

## 6. Contract additions for A7 / A8 / A11

**These are additions to `ADAPTER-SPEC.md` and `INTERFACE-slots.md`. They do not contradict
either document** — every item either restates an existing rule with the concrete case it
applies to, or fills a gap those documents do not cover (array-valued upstream props, repo-2
editing, SVG-id collisions, the "transparent is not always transparent" trap). Where a repo-2 rule
departs from `ADAPTER-SPEC.md` §0.3 rule 1 ("the upstream components are frozen"), that departure
is called out explicitly and is scoped to the repo-2 copies only.

### C1 — Array-valued upstream props

`INTERFACE-slots.md` delivers **one string per slot**. Two upstreams take an **array**:

- `text-mask-reveal` → `lines: string[]` (TextMaskReveal.tsx:18)
- `bar-chart-anim` → `bars: BarItem[]` (BarChartAnim.tsx:32)

**Rule.** Where the upstream prop is `string[]` and the content is textual, the adapter derives
the array from the resolved slot value: split on `\n` first; if there is no newline, split on
single spaces into at most 3 chunks of at most 18 characters each. The adapter must **never** fall
back to the upstream's own placeholder — `text-mask-reveal` falls back to `["REVEAL"]` when
`lines` is empty (`:43`), and that string must never be reachable. If the derived array is
shorter than the upstream's default, pass it as-is.

### C2 — Upstream props that are neither text nor colour

`INTERFACE-slots.md` §1.1 covers *text* slots and `colors[]` covers *colour* roles. It says
nothing about the third class of upstream input: **geometry and timing constants that are not
brand inputs but must still be overridden** when the upstream's default assumes a canvas the
target does not use.

**Rule.** Any upstream prop whose default is expressed in absolute pixels **relative to a
1920-wide canvas** must be computed by the adapter from `props.width` / `props.height`, not
copied from the upstream default. The known case is `logo-split-reveal.splitOffset`, whose default
is **960 px** (`:55`) — the adapter must pass `Math.round(props.width * 0.5)`. Upstream props
whose default is already a *fraction* of the canvas (`logo-bounce-drop.dropHeight = 0.6`) are kept
as-is.

### C3 — Truncation is mandatory where the upstream hardcodes a font size and `nowrap`

`ADAPTER-SPEC.md` §3.6 already mandates truncation for `lower-third-glass-card` because of
`whiteSpace: "nowrap"`. The same trap exists in the new templates and the rule generalises:

**Rule.** Where the upstream hard-codes a font size in px **and** does not wrap, the adapter must
truncate the string it passes. Working limits: ≈ 20 characters for the 260 px wordmarks
(`logo-blur-reveal`, `logo-split-reveal`, `logo-bounce-drop` at 240 px), ≈ 18 characters for the
220 px `glitch-text`, ≈ 24 characters for the 160 px `brush-stroke-reveal` title.
`truncateText()` in `templates/designs/shared.tsx` already does this.

### C4 — "Transparent" is only safe when the colour is consumed as a plain fill

**This is the rule that would have caught the two inventory errors.** Before shipping a template,
read the root `<AbsoluteFill>` **and every colour helper the background is passed to**.

**Rule.** The background prop may be set to the literal `"transparent"` **only** if it is consumed
as a plain `background`/`backgroundColor` value. It must **not** be passed to a hex-parsing
helper, used as a gradient stop that is derived, or fed to a `mix()`/`shade()` function. Known
failures (executed, §1.7): `wave-text` → `shade("transparent", -15) === "#000000"`;
`scramble-text` → `shiftLightness("transparent", 8) === "#001200"`. Both paint an opaque
gradient. **Neither may ship as an overlay.**

### C5 — Non-switchable full-canvas accents must be declared

Some upstreams paint a low-alpha wash over the whole canvas that no prop can turn off:
`text-mask-reveal` (`:91`, a 13 %-alpha accent radial), `chapter-title` (`:184-192`, a 3 %-white
grid at `inset: 0`), `logo-mask-wipe` / `logo-stroke-draw` (a radial badge glow).

**Rule.** A design that paints one of these must (a) say so in `capabilities.notes`, and (b) be
placed at `scale < 1` so the wash stays inside the box. It must not be offered as a full-frame
layer.

### C6 — `mix-blend-mode` inside a design is not the `bokeh-circles` case

`ADAPTER-SPEC.md` §5.7 warns that `mix-blend-mode: screen` is confined by the scale-wrapper's
stacking context. `glitch-text` uses `mixBlendMode: "screen"` (`:147`, `:158`) — but the blend
happens **within the text stack** (the parent `div` carries a `transform`, so it creates the
stacking context), so the R/B layers blend against the centre text layer and **not** against the
video.

**Rule.** Note this in `capabilities.notes` so A11 does not "fix" the blend by removing the
scale-wrapper, and so nobody mistakes it for the bokeh failure mode.

### C7 — Fixed SVG ids: one instance per design per composition

`logo-stroke-draw` uses `clipPath id="lsd-shine-clip"`, `logo-mask-wipe` uses
`clipPath id="lmw-wipe"`, `rve-circular-progress` uses `id="progressGradient"`. Two mounted
instances of the same design duplicate the DOM id and the second may resolve to the first's
definition.

**Rule.** The catalog must allow **at most one instance of a given design per composition**.
Note it in `capabilities.notes` for the affected designs. (The upstream files are frozen, so the
id cannot be namespaced inside the component.)

### C8 — Repo-2 copies are edited; repo-1 copies are frozen

`ADAPTER-SPEC.md` §0.3 rule 1 ("the upstream components are frozen") governs the **Phase 1**
copies in `_upstream/`. Repo 2 cannot be shipped without editing: 78 of its 81 files hardcode
every string, colour and dimension in JSX, and there is no props surface to bind to.

**Rule (scoped to the repo-2 copies under `_upstream/rve-<id>/`):**

1. The copy **is** edited — that is the whole point of batch 2.
2. Every hard-coded string, colour and dimension becomes a **prop whose default reproduces the
   upstream value exactly**, so the copied file still renders the upstream design verbatim when
   the props are left at their defaults. The adapter always passes brand-derived values.
3. The original in-file credit header **must stay at the top of the file**, followed by the
   Phase 2 provenance header.
4. The **motion** (springs, `interpolate` ranges, `delay` arithmetic, geometry constants) is
   **not** touched. A batch-2 edit that changes the choreography is out of scope.
5. The frozen rule still applies to the **repo-1** copies A7 makes in `_upstream/<id>/` — repo 1
   is already prop-driven, so no edit is needed or permitted.

### C9 — Repo-2 `rem` units are not canvas-relative

Repo 2 uses `rem` font sizes (`"5rem"`, `"3rem"`, `"4rem"`, `"8rem"`). `rem` resolves against the
**document** root font size, not the composition, so the same template is 80 px tall in a
1920×1080 and in a 1080×1920 composition.

**Rule.** When A8 parameterises a repo-2 font size, the prop's default must stay the upstream
`"…rem"` string (so the default is faithful), but the **adapter must pass a canvas-relative
value** (e.g. `Math.round(props.height * 0.05) + "px"`) so the design reads correctly on 9:16 and
4:5. The upstream `rem` value must never be what the adapter passes.

### C10 — Credit lines: one per upstream repo, and both must be displayable

`catalog.ts` currently exports a single `REMOTION_DESIGN_ATTRIBUTION` (repo 1) and a single
`REMOTION_DESIGN_LICENSE_NOTICE`. Batch 2 introduces a second upstream, so:

- the repo-1 string and notice **stay exactly as they are** (`© 2026 Trimora Inc. — Remotion
  templates by RenderComp (free-remotion-templates), MIT License. …`);
- A8 must add the repo-2 pair: `Remotion templates by React Video Editor
  (reactvideoeditor.com) — MIT License.` and the permission notice **without** a copyright line
  (repo 2 names no holder);
- `source.attribution` on each repo-2 design carries the repo-2 string, and each repo-1 design
  keeps the repo-1 string;
- the credits surface must be able to show **both** notices when a project uses designs from both
  repos. `getRemotionDesignAttributionLine()` currently returns one string — A11 must make the
  credits surface aggregate the distinct `source.attribution` values actually in use.

### C11 — No render-time font loading, ever

The zero-network property in `noNetworkDuringBrandRender.test.ts` covers `fetch`, `XMLHttpRequest`
and `WebSocket` — but **not** `FontFace.load()`, which is a browser-internal request that the
test cannot see (see §2.3 R1).

**Rule.** A design must never load a webfont at render time. The only permitted font source is
(a) the system stack, or (b) a font **inlined into the composition bundle** by A10's
`templates/designs/fonts.ts` — i.e. a base64 data-URI `@font-face` or an equivalent bundled
`FontFace`, **never a remote URL and never a `public/` asset**.

Why `public/` is not good enough: a `public/fonts/*.woff2` referenced by URL is still a
**network request** when the web-renderer captures a frame — the same-origin kind, so it is less
bad than a `fonts.gstatic.com` call, but it is still a fetch inside the "no network during brand
render" window, and the render would stall on it. (A10's `public/fonts/personalization-sans-latin.woff2`
as of this handoff is a served asset → it needs to become an inlined data URI to satisfy this
rule.) Any upstream that needs `@remotion/google-fonts` — i.e. **all of repo 3** — is out of scope.
**A10 must be told this explicitly**, because "just add the font" is the obvious wrong answer.

### C12 — Determinism gate for any new copy

`ADAPTER-SPEC.md` §0.3 rule 10 requires determinism. A **repo-2 copy that is edited** must be
re-checked for it, because editing can *introduce* a violation. The known cases:

- `typewriter-subtitle.tsx:43` — `Math.random()` is called during render (its result is unused
  today, so the output is still deterministic, but the call is a landmine);
- `typewriter-subtitle.tsx:55` — `transition: "all 0.05s ease-out"` is **wall-clock** driven, not
  frame-synchronised;
- `floating-bubble-text.tsx` — `animation: rotate 3s linear infinite` (excluded outright).

**Rule.** Before a repo-2 copy is registered: `grep -n "Math.random\|animation:\|transition:\|@keyframes"`
must return **nothing** (or the offending lines must have been removed as part of the
parameterisation). The same grep must return nothing for `Date.now()`.

### C13 — Non-brand upstream props are pinned in `defaultProps`, never invented per render

Some upstreams require a prop the customer cannot supply and the brand cannot fill:
`bar-chart-anim.bars: BarItem[]` (`:32`) is required, and `Math.max(...bars.map(...), 1)` on an
empty array yields a chart with no bars.

**Rule.** Such props are pinned in the catalog's `defaultProps` (which already allows arbitrary
upstream props: `defaultProps?: Partial<RemotionDesignComponentProps> & Record<string, unknown>`)
with an **explicitly labelled placeholder** dataset, and the catalog's `capabilities.notes` must
say the data is a placeholder. The adapter must never fabricate data at render time from brand
text, and must never fall through to the upstream's demo dataset (the upstream's
`defaultBarChartAnimProps.bars` contains `"Quarterly Revenue"` / `"Q1"…` — unreachable).
