## Executive summary (one paragraph)

The CI outage is **not** a repository defect and **not** caused by the Phase 1/2 diffs. The
GitHub account that owns `deangilmoreremix/OpenHiggsBolt` is **locked out of GitHub Actions
for a billing reason**, so GitHub refuses to allocate a runner for any job. Every failing job
carries the literal annotation *"The job was not started because your account is locked due
to a billing issue."* Of the **612 workflow runs in the repository's entire history**, exactly
**one** ever obtained a runner (run `38418902330`, 2026-10-13) and **zero** ever concluded
`success`. The Phase-1 baseline commit `84a9d1586` itself is the `head_sha` of the failing
run `39496203903`, which is the strongest possible proof that the failure is independent of
any diff. The repository owner already diagnosed this exact condition on 2026-10-13 in commit
`d3267cee9` ("chore(ci): retire GitHub Actions — Netlify is the build and deployment gate"),
quoting the same annotation, and deleted all eight workflow files; commit `28a1c96d9` then
re-added three of them and silently re-created the outage. **The fix is a billing action by
the account owner (outside the repo).** A repository-side remediation (re-apply the owner's
own retirement, or restrict the two PR workflows to `workflow_dispatch`) is provided as an
unapplied patch. Full detail and the unabridged patch: `docs/ci/CI_OUTAGE_REPORT.md`.

  red until the next PR; removing/restricting the workflows alone leaves CI unable to run.
  Both axes are documented, with a clear recommendation (billing first; the repo-side
