## Decisions

- **Fix the `any`s with real types rather than narrowing the rule** — the task allowed a "narrow
  structural type"; where a real type existed (`DemoPersonalizeContextValue`,
  `PersonalizationSource`) I used it, and where none did (the mocked social-publish context, the
  `fetch` stub, the debug hook) I declared a small structural type in the test file itself. A rule
  suppression would have made the file lint-clean while leaving it type-unsafe, and the point of
  the fix is the opposite.
- **Use `satisfies SocialPublishContextStub` instead of a double assertion** for the mocked
  context — it is a type-only construct (erased at compile time), so the hoisted `vi.mock` factory
  gains no runtime dependency, and it checks the object against the type rather than forcing it
  through it.
- **Type `DEMO_SOURCE` as `PersonalizationSource`** — a supporting change that makes the test
  file *stricter* than before (the literal `mediaType: 'video'` is now checked against the real
  union `'image' | 'video' | 'prompt-only'`, which it would not have been with an inferred `string`).
- **Re-measure the baseline instead of quoting it** — V1's baseline numbers were re-derived with
  the same method on a pristine `git archive` tree. The method reproduces V1's numbers exactly
  (251 / 1224 / 495 / 1719), which is what makes the delta trustworthy.
- **Correct V1's "`next lint` always exits 0" note in the report** — it is not reproducible in
  Next 15.5.15; the command exits 1 whenever ESLint reports an error. A5 recorded exit 1 too. The
  finding counts remain the signal.
- **Do not take the build lock** — the lint fix needed only a scoped `next lint` and a single-file
  `vitest run`, neither of which needs the lock, and the lock was `FREE` for my whole window.
- **Write the E2E raw output into the report byte-for-byte** — the report's four E2E code blocks
  were diffed line-by-line against `docs/phase2/raw/row{7,8,9,10}*.txt` and
  `docs/phase2/raw/rows7-10-combined.txt`; all five are identical.
