## Decisions

- **Used a pristine `git archive 84a9d1586` tree instead of `git stash` for every baseline proof**
  — the spec’s proof rule says “stash → re-run at baseline → pop”, but stashing mutates the shared
  working tree while V2 is live in it (V2 is running E2E against the same files). `git archive`
  gives the identical comparison with zero risk of losing another agent’s work. This is the same
  method A5 and A11 used and that the orchestrator already accepted (A5 handoff
  §“Gate 1”, A11 handoff §4).
- **Re-measured the Phase 1 lint baseline instead of quoting A5’s number** — the counting method
  was validated by reproducing A5’s 251 / 1224 / 495 / 1719 exactly on the baseline tree, which
  makes the ±7/−2 delta trustworthy on both sides.
- **Normalised line numbers when diffing the two lint runs** — Phase 2 added lines to files, so
  every `line:col` moved; comparing raw strings produced 4 phantom “changed” files. Comparing
  `(rule, message)` multisets per file produced the true delta.
- **Ran row 5 three times, including a `--maxWorkers=2 --minWorkers=1` run** — the default-worker
  runs disagreed with each other (2 failures, then 3), which the spec says to treat as a load
  symptom until proven otherwise. The low-contention run is the trustworthy number, and the extra
  failure was then proven at the baseline.
- **Did NOT fix the 7 new lint errors** — the spec says report product bugs, do not fix them.
- **Did not use `next dev`/Turbopack and did not touch port 3111** — rows 1–6 need no server.
