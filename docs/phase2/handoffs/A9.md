## 1. What was built

Phase 1 built the shared hand-off `src/shared/personalization/studioEntry.ts` and wired **one** studio
(Video Studio) by importing `PersonalizeStep` **across the `packages/studio` package boundary**
(`../../../../src/shared/personalization/studioEntry`). A5 proved that import is unsound:
`packages/studio/package.json` has `main`/`module` = `src/index.js` and `files: ["src","dist"]`, so
`src/` **is** the published entry point and the cross-package import would ship into the published
tarball pointing at a repo-only path.

**A9 therefore added ZERO new imports to `packages/studio`.** Each of the nine studios now:

1. builds a plain `StudioPersonalizeOptions` **object** in a local `useMemo` (no import needed — it is
   plain data), and
2. accepts an **optional render prop** `renderPersonalizeAction` that the **app root** (A11) passes in,
   and
3. renders `{renderPersonalizeAction?.(studioPersonalizeOptions)}` next to the studio's existing
   media preview chip.

The only import change in all nine files is adding `useMemo` to the **existing** `react` import
statement. See §5 for the raw before/after diff proving no new import line — and therefore no new
cross-package import — was added.

### 1.1 The exact render-prop pattern

Every one of the nine studios uses this identical shape.

**Prop declaration** (inside the component's destructured props, with a JSDoc block):

```jsx
  /**
   * Optional renderer for the shared Personalization Modal hand-off.
   *
   * The `studio` package is published standalone, so it MUST NOT import the
   * app's `src/shared/personalization/studioEntry` module — the app root owns
   * that wiring and passes the renderer in.
   *
   * The argument is a plain `StudioPersonalizeOptions` object:
   *   { originStudio, studioProjectId, title,
   *     media: { mediaType, url, poster, aspectRatio, duration, durationLabel },
   *     prompt: { text, model, modelName } }
   */
  renderPersonalizeAction,
```

**Memo** (one per studio, no imports):

```jsx
  const studioPersonalizeOptions = useMemo(
    () => ({
      originStudio: "<slug>",
      studioProjectId: [ /* stable, unique-per-project parts */ ].join(":"),
      title: "…",
      media: {
        mediaType: "image" | "video",
        url: <source media url> || null,
        poster: null,
        aspectRatio: <ar>,
        duration: <seconds>,
        durationLabel: `${<seconds>}s`,
      },
      prompt: { text: <prompt>, model: <model id>, modelName: <model name> },
    }),
    [ /* deps */ ],
  );
```

**Render call** (next to the media preview chip):

```jsx
{studioPersonalizeOptions.media.url
  ? renderPersonalizeAction?.(studioPersonalizeOptions)
  : null}
```

The studio-side `media.url` guard is what makes the trigger **appear only when there is source
media**; the app-root `PersonalizeStep` has the same guard, so the button is absent in both cases.

### 1.2 Expected shape for A11 to type at the app-root call site

`renderPersonalizeAction?: (options: StudioPersonalizeOptions) => React.ReactNode`

where `StudioPersonalizeOptions` comes from
`import type { StudioPersonalizeOptions } from '@/shared/personalization/studioEntry'`.
Inside `packages/studio` the prop is **untyped** (the files are `.jsx`), so the package needs no
dependency on the app's types.

## 3. Judgement calls (read this before reviewing)

### 3.1 "Source media" = the studio's own primary media, not the newest generated output

The reference implementation (Video Studio, Phase 1) hands over the **uploaded** source clip, and the
Phase 1 report §7.4 lists "Source media" per studio as the studio's input asset. I followed that
rule everywhere, with two documented exceptions (Vibe Motion, AI Influencer) where the studio has
**no upload input at all** and the newest generation is the only media there is.

Consequence: for Clipping / Motion Control / Recast / Lip Sync / Marketing, the trigger appears as
soon as the user has uploaded their source, and the Personalization Modal personalizes that source.
The studio's *generated* output is not handed over. If the team wants the generated result instead,
that is a one-line change per studio (`media.url`) — but it is a product decision, not a bug.

### 3.2 Multi-asset studios: the single primary asset is handed over, the rest is dropped

`StudioPersonalizeOptions` carries exactly **one** `media`. For the studios that compose several
assets, I picked the primary one and documented the choice:

- **Motion Control** — reference video (`videoUrl`); the up-to-30 character images are dropped.
- **Recast** — source video (`videoUrl`); the character image is dropped.
- **Lip Sync** — the subject in the current `inputMode` (image or video); the audio track is dropped.
- **Marketing** — the product image; the avatar and the reference images are dropped.
- **Cinema** — the uploaded reference image; if there is no upload, the newest generated shot.
- **Image Studio** — `uploadedImageUrls[0]`; the remaining uploaded images are dropped.

The `initialAssets` / `returnPayload` fields of the contract exist for exactly this kind of
multi-asset case, but filling them needs the app-root's brand-asset library, which the studio
package cannot reach. A11 can enrich the options at the app-root call site.

### 3.3 `CinemaStudio` is an IMAGE studio, not a video studio

`docs/REMOTION_PHASE_1_REPORT.md` §7.4 lists Cinema Studio's source media as "video". That is
wrong for `packages/studio/src/components/CinemaStudio.jsx`: it imports
`{ generateImage, uploadFile }` from `../muapi.js` and calls `generateImage` (line ~672) — it
generates **images**. The hand-off therefore uses `mediaType: "image"`. **Correction for the Phase 2
report.**

### 3.4 `AiInfluencerStudio` trigger sits inside an absolute-positioned overlay

The AI Influencer preview is a `relative` box whose Publish/Assist buttons are absolutely positioned
(`absolute bottom-3 right-20` / `right-36`). The render call is placed in the same overlay row, so
**A11 must give the returned node an absolute positioning class** (e.g.
`absolute bottom-3 right-52 ...`) or it will appear as a normal flow child of the preview box.
Every other studio's trigger is in a normal flex row and needs no special class.

### 3.5 `VibeMotionStudio` has no media chip in its prompt bar

Vibe Motion's media previews are the **gallery cards**, and only ONE render call per studio is
allowed, so the trigger cannot live on every card. It sits at the end of the bottom prompt bar's
textarea row and personalizes `history[0]` — the newest generation. If the team wants per-card
triggers, that is a per-card render-prop change (the options object would need to be built per
entry, not once).

### 3.6 `LipSyncStudio` has no aspect ratio and no duration state

Neither exists in the file, so `media.aspectRatio` / `media.duration` are simply absent from the
options (the contract marks them optional). Same for Clipping and Recast (no duration) and for
Image / Cinema / AI Influencer (no duration — still images).

### 3.7 Slugs: **no union addition is required**

`PersonalizationOriginStudio` in `src/shared/personalization/studioEntry.ts` (lines 51-74) already
contains a literal for every one of the nine studios: `'image'`, `'clipping'`, `'vibe-motion'`,
`'motion-control'`, `'lipsync'`, `'cinema'`, `'marketing'`, `'recast'`, `'ai-influencer'`.

**A11 does NOT need to widen the union.** Two slugs differ from the names in my task brief, and I
deliberately used the literals that are already in the union rather than editing a file I do not own:

| Task brief suggestion | Literal used | Why |

| `ai-clipping` | `clipping` | `'clipping'` is already in the union; `'ai-clipping'` is not. |
| `lip-sync` | `lipsync` | `'lipsync'` is already in the union; `'lip-sync'` is not. |

If the team prefers the hyphenated names, A11 must add `'ai-clipping'` and `'lip-sync'` to the

## 6. Decisions

- **Render prop instead of a direct import** — `packages/studio` publishes `src/`, so importing
  `src/shared/personalization/studioEntry` from inside the package would ship a repo-only path into
  the published tarball (A5's finding). The render prop keeps the package self-contained: the nine
  studios import **nothing** new.
- **Studio-side `media.url` guard on the render call** — makes "the trigger appears only when
  there is source media" a property of the studio, so it is unit-testable without the app root.
  (The app root's `PersonalizeStep` keeps its own identical guard, so there is no double-open risk.)
- **Existing union slugs reused** (`clipping`, `lipsync`) instead of `ai-clipping` / `lip-sync` —
  `studioEntry.ts` is not A9's file, and reusing the existing literals keeps the union unchanged.
- **Uploaded source media over generated output** — matches the Phase 1 Video Studio reference
  implementation and the Phase 1 report's "Source media" column; exceptions documented in §3.1.
- **`originStudio` slug = the studio's own id** for every studio, so the persisted project can be
  attributed to the studio that created it.
