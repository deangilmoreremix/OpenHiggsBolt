## Decisions

- **The primary slot keeps `layer.text`; only the secondary slots get a new field** — the primary
  slot is already persisted (`normalizeLayer` keeps `text`), already rendered and already
  editable, so reusing it means the existing behaviour is provably unchanged and A11's delta
  stays as small as possible. → A11 adds exactly one optional field.
- **`textSlotOverrides?: Record<string, string>`, keyed by `RemotionDesignTextSlot.key`** (not by
  `field`) — two slots may legitimately share a brand field, and the key is the stable, persisted
  identity of a slot. → the map survives a design changing which brand field feeds a slot.
- **An override is effective only when it is a non-empty string; otherwise the brand value wins**
  — an override must never render an empty slot, and "clear the field" then means "reset to the
  brand value", which is what the customer sees. The inspector removes the key when the field is
  cleared, so the persisted state stays clean.
- **The primary slot keeps the legacy "presence" rule** (`layer.text` wins even when it is an
  empty string) — that is exactly what the composition does today, so the inspector and the
  render cannot disagree.
- **The inspector reads the new field defensively** (a local cast + a runtime guard) so it
  compiles and works against today's `PreviewLayer`, and a project saved before the field
  existed keeps rendering the brand values. → the feature does not break while A11 has not landed
  the type change.
- **The resolver is exported from `OverlayEditor.tsx` and duplicated there on purpose** — it is
  the only file A4 owns. The composition must **not** import it from `guided/` (that would create
  the cycle `PersonalizationComposition → OverlayEditor → DemoPersonalizeProvider →
  PersonalizationModal → OverlayEditor`). A11 is asked to move the helper into the `core` lane
  and import it from both sides. → the duplication is temporary and explicitly assigned.
- **A registered design with no slots renders "This design has no editable text."** instead of the
  old generic "Text" field (the bokeh effect declares no slots). A design that is *not*
  registered keeps the old single text field, because there is no slot list to render.

## Interface changes (consumers must know)

Full contract: **`docs/phase2/INTERFACE-slots.md`**. Summary:

1. **`src/shared/personalization/preview/types.ts` → `PreviewLayer` (A11, `core` lane) — add:**

   ```ts
   /**
    * Per-slot text overrides for a `design` layer, keyed by
    * `RemotionDesignTextSlot.key`.
    *
    * The PRIMARY slot is NOT stored here: it keeps using `layer.text`.
    * Only the secondary slots appear in this map, so a design that declares
    * no primary slot stores every slot here.
    *
    * Absent ⇒ the slot falls back to its brand field.
    */
   textSlotOverrides?: Record<string, string>
   ```

2. **`src/shared/personalization/preview/presets.ts` → `normalizeLayer()` (A11) — preserve it.**
   `normalizePreviewSettings()` needs **no** change (it builds every layer through
   `normalizeLayer()` and then `clampLayer()`, which spreads the layer):

   ```ts
   // in normalizeLayer(), after the `designId` handling:
   const textSlotOverrides = normalizeTextSlotOverrides(raw.textSlotOverrides)
   if (textSlotOverrides) normalized.textSlotOverrides = textSlotOverrides
   ```

   ```ts
   function normalizeTextSlotOverrides(raw: unknown): Record<string, string> | undefined {
     if (!isRecord(raw)) return undefined
     const out: Record<string, string> = {}
     for (const key of Object.keys(raw)) {
       const value = raw[key]
       if (typeof key !== 'string' || !key) continue
       if (typeof value !== 'string') continue
       out[key] = value
     }
     return Object.keys(out).length > 0 ? out : undefined
   }
   ```

3. **`src/shared/personalization/preview/presets.ts` → `applyDesignTemplate()` (A11) — carry the
   overrides over** so re-applying the same design does not drop the customer's edits:

   ```ts
   const textSlotOverrides =
     existing?.designId === design.id ? existing.textSlotOverrides : undefined
   // …
   if (textSlotOverrides) overrides.textSlotOverrides = textSlotOverrides
   ```

4. **`src/shared/personalization/preview/PersonalizationComposition.tsx` →
   `resolveDesignTextSlots()` (A11) — render the overrides:**

   ```ts
   const overrides = layer.textSlotOverrides
   for (const slot of declared) {
     if (!slot || typeof slot.key !== 'string') continue
     if (slot.primary && typeof layer.text === 'string') {
       slots[slot.key] = layer.text
       continue
     }
     const override =
       overrides && typeof overrides[slot.key] === 'string' ? overrides[slot.key] : undefined
     slots[slot.key] = override && override.trim() ? override : brandTextValue(slot.field, brand)
   }
   ```

5. **Move the resolver into the `core` lane (A11, recommended).** `resolveDesignSlotValues()`,

6. **`src/shared/personalization/templates/types.ts` → `RemotionDesignTextSlot` (A11) — add the

  the **composition still renders the brand value** for that slot, because
  `resolveDesignTextSlots()` in `PersonalizationComposition.tsx` does not read
  `textSlotOverrides` yet. The inspector and the render agree only after that change. The exact
  patch is in `docs/phase2/INTERFACE-slots.md` §4.4.

  field existed keeps rendering the brand values.

  temporary shim, not a substitute.
