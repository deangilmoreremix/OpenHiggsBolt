## Decisions

- **Ten of ten candidates shipped; no substitutions.** Every candidate in the A6 list was
  re-verified in the clone before it was implemented, and all ten turned out to be overlay-able.
  `wave-text` and `scramble-text` were **not** used, exactly as A6 instructed. No candidate
  failed verification, so no substitution was needed. Every design declares
  `capabilities.browserExport: true` with a truthful note.
- **The frozen upstream copies are byte-identical.** Each copy is the upstream file with the
  8-line provenance header prepended, and the header is the exact format used by the existing
  `_upstream/bokeh-circles/BokehCircles.tsx` (only the phase line reads "Phase 2" instead of
  "Phase 1"). The SPDX lines the upstream itself carries are kept directly underneath, so the
  MIT notice is never separated from the code it covers.
- **`_upstream/<id>/` is named after the catalog id, not the upstream folder.**
  `starfield-warp` therefore lives in `_upstream/starfield-warp/Starfield.tsx` while its
  `source.sourcePath` is the real upstream path `src/components/starfield/Starfield.tsx` — the
  path the provenance table and the licence audit use.
- **The adapters import the deterministic font stack through `designs/fonts.ts`.** Each adapter
  calls `useDesignFonts()` (A10's hook, re-exported by `./fonts`), which injects the
  `@font-face` + `!important` override stylesheet so the frozen upstreams' inline
  `font-family` is replaced by the bundled "Personalization Sans" stack. No new system-font
  stack was introduced anywhere in this lane, and the upstreams' own constants are untouched.
  A11's pending `DesignStage` edit will make the call redundant (a second gate is harmless).
- **Fixed-px display sizes are computed from the composition width, not copied.** The upstream's
  `fontSize: 240` (bounce-drop), `260` (split-reveal, blur-reveal) and `220` (glitch) are
  hard-coded for a 1920 px canvas. The adapter keeps the upstream value as the **upper bound**
  and shrinks it so the wordmark fits the title-safe width on a 1080 px canvas — so a 16:9
  composition keeps the upstream look and a 9:16 / 4:5 composition does not overflow. This is
  A6's C2 applied to values C2 did not enumerate.
- **Text is truncated to a per-design cap** (A6's C3): 20 characters for the 240/260 px
  wordmarks, 18 for the glitch headline (`whiteSpace: "nowrap"`), 24 for the 160 px brush-stroke
  title, 28 for the mask-wipe wordmark, 48 for the chapter/bar-chart copy.
- **The starfield renders 60 stars, not the upstream's 180.** Every star is an absolutely
  positioned div with a gradient and a glow, and the effect runs for 150 frames; 180 shadowed
  elements per frame is a heavy full-frame effect over a customer's video. This is the same call
  the Phase 1 bokeh adapter made (24 → 16 discs). 60 streaks still read as a full warp field,
  and it keeps the render cost (and the jsdom test cost) sane on a loaded host.
- **The bar-chart dataset is pinned in `defaultProps` and exported from the adapter.** The
  upstream's `BarItem` type is not exported, so the adapter declares a structurally identical
  `BarChartPlaceholderBar` and exports `BAR_CHART_PLACEHOLDER_BARS`; `catalog.ts` pins exactly
  that constant in `defaultProps.bars`, so there is one source of truth and no demo data can
  leak in.
- **`catalog.test.tsx` was updated (out of lane, see above).** The four assertions that
  hard-coded "five designs" / "one design per category" had to change; every assertion about
  the five Phase 1 designs themselves was kept and still passes.
- **The shared `designs/index.ts` barrel was NOT touched.** A8 is running in parallel and the
  barrel is a shared file; writing to it could collide. `catalog.ts` imports the ten batch-1
  adapters directly from their modules instead. A11 may add the barrel re-exports once both
  lanes have landed.

## Open questions / blockers

- **`logo-mask-wipe` uses a fixed SVG `clipPath` id (`lmw-wipe`).** Two mounted instances of the
  same design in one composition would share the DOM id and the second wipe would be clipped by
  the first. This is declared in `capabilities.notes`; it is not fixable without editing the
  frozen upstream. A11 should decide whether the Step 4 UI needs to warn about it.
- **`chapter-title`'s subtitle is a hard-coded `rgba(255,255,255,0.6)`** in the frozen upstream.
  It is low contrast over a light video and cannot be restyled from the adapter. Declared in
  `capabilities.notes`.
- **The ten new designs declare no `media` role**, so none of them renders the customer's logo
  image — the upstream templates they wrap have no image prop (the one that looks like one,
  `logo-bounce-drop`'s `svgPath`, takes SVG *path data*, not a URL, and is pinned to `""`).
  The existing `logo-reveal` design remains the one that shows the customer's logo.
- **The Phase 2 report needs the MIT credit line for the new designs.** The attribution string
  is unchanged from Phase 1 (same repository, same licence), so the product-side credit surface
  needs no new entry — only the `_upstream/README.md` provenance table grows.
