### 0.1 Access limitations (explicit — nothing below is fabricated)

1. **`remotion-templates` has NO `LICENSE` file at the repository root.** The only licence
   statement is prose in `README.md` § *License*: *"All templates in this repository are available
   under the MIT License. You can use them in personal and commercial projects, but attribution is
   appreciated where applicable."* Every template file additionally carries an in-file header:
   *"Free Remotion Template Component … This template is free to use in your projects! Credit
   appreciated but not required. Created by the team at https://www.reactvideoeditor.com"*.
   **There is no MIT copyright line and no named copyright holder for this repo**, so the
   "retain the copyright notice" clause has nothing to name. It is recorded here as *MIT, attribution
   optional (strongly recommended)* with the in-file header as the exact credit line.
2. **14 templates published on the React Video Editor gallery are NOT in the cloned
   `remotion-templates` repo** (see §5.2). Their source could not be inspected, so they are
   recorded as gallery entries only and never counted as repo rows.
3. `remotion-video-templates` ships `public/logo.svg`, `public/screenshot-1.svg`,
   `public/screenshot-2.svg` and `public/captions.sample.json`. All four are referenced through
   `staticFile()` / a build-time JSON import, which is one of the disqualifiers for browser export.
4. `free-remotion-templates` ships an `ASSETS.md` inventory stating that **zero** font, image,
   audio or video files are bundled: *"All graphics are drawn in code (inline SVG / CSS)"* and the
   only font references are the system stacks `-apple-system, "Segoe UI", Roboto, sans-serif` and
   `"SF Mono", "Menlo", "Consolas", monospace`. This was independently confirmed by scanning
   `src/` for `@font-face`, `url()`, `data:` URIs and binary extensions — 0 hits.

**Legal note.** MIT requires the *copyright notice and the permission notice* to be reproduced
alongside any substantial portion of the software. The permission notice is the body of the MIT
licence text. For the five templates actually shipped in Phase 1 the obligation is therefore:

- Reproduce, verbatim, the MIT licence body and the line `Copyright (c) 2026 Trimora Inc.`.
- Display the `MIT-TRIMORA` attribution string in the product UI (credits / "About" / export
  credits panel).
- Keep each copied file's SPDX header and the `SMARTVIDEO GO AI — Phase 1 upstream template`
  header block (already done, see `src/shared/personalization/templates/_upstream/`).

**Remotion itself is separately licensed** (not MIT). It is already a dependency of the target
repo (`remotion@4.0.499`), so no new obligation is created by this task, but any commercial
launch must comply with <https://remotion.dev/license>.

## 8. Risks for the integration agent

1. **Fonts.** All five selected templates use the system stack
   `-apple-system, "Segoe UI", Roboto, sans-serif`. No `@remotion/google-fonts`, no `@font-face`,
   no webfont download. Consequence: **the rendered face is machine-dependent** — a Linux CI box
   without `Segoe UI` falls back to Roboto/DejaVu, so line breaks and letter-spacing can differ
   between the preview (`<Player>` in the user's browser) and an exported file. The target repo
   already has a `fontStackById()` helper in
   `src/shared/personalization/preview/presets.ts` — prefer passing a brand font stack in.
2. **Hardcoded pixels.** `bounce-in-headline` hardcodes `fontSize: 130` and `letterSpacing: 6`;
   `logo-stroke-draw` is fully relative (`R = height*0.2`, `fontSize = height*0.05`) and needs no
   change; `lower-third-glass-card` is fully relative; `end-card` uses `height*0.075` /
   `width*0.075` with a portrait switch; `bokeh-circles` is fully relative. The headline is the
   only one that must be parameterised for 1920×1080 / 1080×1920 / 1080×1080 / 1080×1350.
3. **fps assumptions.** Every selected template is fps-agnostic **except** `bounce-in-headline`,
   whose `delay` (8) and `duration` (36) are expressed in **frames** and whose `height` (120) is
   pixels. At 30 fps the effect is 8→44 frames; at 60 fps it is twice as long in wall-clock terms.
   `logo-stroke-draw`, `lower-third-glass-card`, `end-card` and `bokeh-circles` are all
   frame-based too, but the target renders at 30 fps today, so they are stable.
4. **Backdrop-filter (`lower-third-glass-card`).** If `backdrop-filter: blur(14px)` is dropped by
   the browser rasteriser, the card degrades to a translucent white gradient over the video — still
   legible, not broken. Verify visually before shipping.
5. **Blend mode (`bokeh-circles`).** `mix-blend-mode: screen` only blends against the video if no
   ancestor creates a stacking context. **Do not** wrap the effect in an element with
   `opacity < 1`, `transform`, `filter`, `isolation: isolate` or `mix-blend-mode` — that
   confines the blend to the wrapper and the bokeh renders as flat translucent discs.
6. **Fixed SVG ids (`logo-stroke-draw`).** The shine sweep uses `clipPath id="lsd-shine-clip"`.
   Two instances mounted at once (e.g. the preview `<Player>` and the web renderer in the same
   page) produce a duplicate DOM id; the second instance's clip may resolve to the first. The
   clip shape is identical, so the visual result is unchanged, but it is a latent hazard.
7. **`end-card` CTA colour coupling.** `labelColor={background}` means the CTA text colour and
   the card fill are the same value. Any adapter that wants a different CTA text colour must keep
   the card fill readable, or accept the upstream constraint.
8. **No `staticFile()`, no `<Video>`, no `<Audio>` in any of the five** — the templates are
   self-contained DOM/CSS/SVG, so they render identically in `<Player>` and in
   `@remotion/web-renderer`, and the user's real video stays the background layer.
