# Netlify Deployment Repair — Production Deploy Pipeline

## 1. Summary

| Field | Value |
|-------|-------|
| Date | 2026-10-09 to 2026-10-10 |
| Scope | Netlify GitHub → production deploy pipeline for <https://go.smartvid.app> (site `76f606a3-8546-440f-8469-33a0236a8a23`) |
| Outcome | Git-triggered builds green; live production deploy verified (`6ac97d41ca4eb5000917b585`, commit `0136f466`) |

Every git-triggered build was failing while CLI `--no-build` deploys reported "passed". Three stacked defects (a stale Netlify repo cache, an npm-only patch mechanism running under pnpm, and missing Netlify environment variables) plus a pnpm version/lockfile mismatch kept the build from ever reaching `next build`. This document records the root-cause chain, the fixes, the verification evidence, and the runbook for future incidents.

## 2. Symptoms

- Every git-triggered build failed, approximately 20–26 seconds after start — far too fast for a real build, confirming failure during clone/install rather than compilation.
- CLI deploys using `--no-build` reported "passed" but are pre-built uploads: they do not run the pipeline and do not count as evidence the Git-based build works.
- The last successful full git build before the incident was **Oct 8, 12:07 UTC, commit `0c190da4`** ("merge(ai-assistant-for-images): add edit persistence fallback regression tests"). No git build succeeded after that until the repair.

## 3. Root Cause Chain

Three independent failures were stacked; each one alone would have failed the build. Evidence below was retrieved from Netlify build logs via `netlify api getSiteBuild` — never guessed.

### 3.1 Stale Netlify repo cache (failure at "preparing repo")

Builds failed while preparing the repo:

```
Fetching submodule packages/Open-AI-Design-Agent at commit 44d168e ...
fatal: remote error: upload-pack: not our ref 36bdba26ae36a5cc73e6c2cb8e5ec5759d98f741
```

The submodule had already been removed from `.gitmodules` and from the tree — the trees at `3a9d1d0a`, `a031a3f8`, and `d66432ab` contain only the `Open-Poe-AI` and `Vibe-Workflow` gitlinks. The failure came from cached clone state populated during earlier failing builds, not from the repository.

**Fix:** cache-cleared rebuild via the Netlify API (note: a branch build does **not** publish production):

```bash
netlify api createSiteBuild --data '{"site_id":"76f606a3-8546-440f-8469-33a0236a8a23","branch":"<branch>","clear_cache":true}'
```

### 3.2 Patch mechanism assumed npm's flat node_modules; Netlify uses pnpm

Netlify runs `pnpm install` whenever a `pnpm-lock.yaml` is present, which installs with an isolated `node_modules/.pnpm` layout — not npm's flat layout. Two consequences:

1. `postinstall: patch-package` failed:

   ```
   Patch file found for package html-encoding-sniffer which is not present at node_modules/html-encoding-sniffer
   ```

   The patch fixes `html-encoding-sniffer@6.0.0` (a direct dependency of `jsdom@29.1.1`) which requires the ESM-only `@exodus/bytes/encoding-lite.js` from CommonJS.

2. The `prebuild` guard `scripts/verify-html-encoding-sniffer-patch.mjs` checked only the root `node_modules` path and exited 1, so the build never reached `next build`.

**Fix:**

- pnpm-native `patchedDependencies` in `pnpm-workspace.yaml` plus patch file `patches/html-encoding-sniffer@6.0.0.patch` (generated via `pnpm patch` / `pnpm patch-commit`), with the corresponding `pnpm-lock.yaml` entry.
- Guard rewritten to resolve the package from jsdom's package root, so it works under both npm-flat and pnpm-isolated layouts; `patch-package` is kept as a fallback for flat layouts.
- `postinstall` removed from `package.json`.

### 3.3 Missing Netlify environment variables

The site had only 10 environment variables. `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` — required at build time by the eager browser client in `src/lib/supabase.ts` (module-scope `getBrowserClient()`) — and all Clerk keys were missing. `next build` failed at page-data collection:

```
Error: Missing NEXT_PUBLIC_SUPABASE_URL or NEXT_PUBLIC_SUPABASE_ANON_KEY environment variable
```

(for route `/api/personalization/record`).

**Fix:** imported 11 variables from `.env.production` (the file's documented purpose) — note `.env.*` is gitignored (`.gitignore:37`), so the source of truth is local-only:

```bash
netlify env:set <KEY> <value> --site 76f606a3-8546-440f-8469-33a0236a8a23 --force
```

### 3.4 pnpm version / lockfile mismatch

pnpm 10 running with `--frozen-lockfile` rejects a lockfile generated by pnpm 12 (`ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` on the `patchedDependencies` hash).

**Fix:** pin `packageManager: pnpm@10.30.3` in `package.json` and regenerate `pnpm-lock.yaml` with pnpm 10. Frozen install verified green under both pnpm 10 and pnpm 12.

### 3.5 Netlify type-check dependency declarations

Next.js type checking failed on modules imported by root app code but absent from `package.json` declarations. Added (additive declarations only, no version bumps):

- `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities` (`1f83300dd`)
- `cheerio` (`1f83300dd`)
- `playwright` (`0bf4ca86f`, dynamic import in `browserDiscovery`)
- `react-markdown`, `remark-gfm` (`ce806e986`, academy components)

## 4. Test-Suite Repair

Commit `b0adcef5a` changed two service contracts without updating the personalization mocks, leaving `DemoPersonalizeProvider.test.tsx` with **16 of 55 tests failing on main** — the suite's only failing file:

- `uploadPersonalizationAsset(apiKey, { file }) => Promise<{ url }>` (was `({ apiKey, file }) => Promise<string>`): string mocks destructured to `url === undefined`; single-arg concurrent mocks read `opts.file` on the apiKey string and threw `TypeError` inside `setTimeout`.
- `persistEditedPersonalizationAsset` now returns `{ ok, assetId, publicUrl }` (was `{ ok, url }`): success-path mocks set the obsolete `url` field.

Fix (`c8b7d3242`, test-only, +30/−42, no source/assertion/behavior changes):

- Upload mock return values wrapped in `{ url }` across durable, retry, fallback, regression, and limit tests.
- Four concurrent-upload mocks migrated to the two-arg signature, eliminating 11 unhandled TypeErrors.
- `publicUrl` (not `url`) set in the two persistence success mocks; explicit `{ ok: false }` persist mocks added to the saved-client regression tests so the upload fallback no longer relies on a caught TypeError.
- Stricter fetch mocks.

**Result: 69/69 files, 760/760 tests.**

Operational note: the historical failure count varied (16 → 28 → 66) purely from CPU-load-induced 5s vitest timeouts. When triaging, re-run the failing file in isolation under low load before believing a failure count.

## 6. Operational Runbook — "Netlify build is failing"

1. **Fetch the real error — never guess.** Get the deploy JSON, then the build log:

   ```bash
   curl -s "https://api.netlify.com/api/v1/sites/76f606a3-8546-440f-8469-33a0236a8a23/deploys?limit=5"
   printf '\n' | netlify api getSiteBuild --data '{"site_id":"76f606a3-8546-440f-8469-33a0236a8a23","build_id":"<build_id from the deploy JSON>"}'
   ```

2. **Map the failure stage:**

   | Stage | Suspect | Action |
   |-------|---------|--------|
   | "preparing repo" | Stale submodule/cache state | Cache-cleared rebuild on a **branch** (see 3.1 — main builds auto-publish production) |
   | "Install dependencies" | Lockfile / package-manager version | `pnpm install --frozen-lockfile` locally with pnpm 10.30.3; keep `packageManager` pinned |
   | "build command" | Missing env vars or code error | `netlify env:list` (step 3); then inspect code |

   ```bash
   pnpm install --frozen-lockfile
   ```

3. **Environment variables** (the human-readable table truncates in non-TTY output — parse JSON instead):

   ```bash
   printf '\n' | netlify env:list --site 76f606a3-8546-440f-8469-33a0236a8a23 --json
   ```

   Source of truth is `.env.production` (gitignored). Re-import missing vars with the `netlify env:set` command in 3.3.

4. **Reproduce locally under CI conditions.** Use a CLEAN worktree and the exact `netlify.toml` build command, with submodules initialized and env files copied in:

   ```bash
   git worktree add /tmp/netlify-repro HEAD
   cd /tmp/netlify-repro
   GIT_SUBMODULE_DEPTH=1 git submodule update --init --recursive
   pnpm install --frozen-lockfile
   cp <main-repo>/.env.production .env.local
   CI=true pnpm run build:metadata && CI=true pnpm run build:packages && CI=true pnpm run build
   ```

   Warning: the build takes roughly 7–23 minutes depending on machine load. Do not conclude failure from a tool timeout — run long builds as a background process and read its logs.

5. **Distinguish load-flakiness before filing defects.** vitest 5s timeouts and build stalls appear under load average > 100 with < 2 GB disk free. Re-run the failing file in isolation under low load first.

## 7. Known Operational Risks / Follow-ups

- **Disk pressure.** ~25 git worktrees each carrying 1–4.3 GB of `node_modules`/`.next` caused a 100%-full disk, which both blocks worktree creation and contributes to build stalls. Mitigation: prune stale worktrees (`git worktree remove <path>`) and their `.next` directories — `.next` is regenerable.
- **`.gitmodules` residue.** The file still lists `packages/timeline-studio` and `apps/headshot-generator`, but no gitlinks for them exist in the tree (verified unused; harmless — `git submodule update` only acts on indexed gitlinks). Clean up opportunistically.
- **Dirty build artifacts.** `packages/studio/dist/muapi.js` is a tracked build artifact that rebuilds dirty; untracked `storage/` (Crawlee runtime artifacts) appears after test runs. Never commit with `git add -A` in these worktrees.
- **Multi-lockfile warning.** The Next.js warning about the root `pnpm-lock.yaml` plus a worktree `pnpm-lock.yaml` is pre-existing and cosmetic; `outputFileTracingRoot` can silence it if desired.
- **PR #44** (`fix/netlify-git-deployment`) was closed as redundant after its content reached `main` via `e7558ccd`; the branch is retained for reference.
- **Product follow-ups.** The personalization feature suite has separate, pre-existing product-level follow-ups outside this repair's scope; none block deployment.

## 9. Rollback

- **Deployment fix:** `git revert e7558ccd6`. This restores `postinstall: patch-package`, the flat-only guard, and the removed submodule gitlink — and will re-break the Netlify build, so only revert if replacing it with a better fix.
- **Test fix:** `git revert c8b7d3242` — restores the 16 contract-mismatch failures.
- **Environment variables:** unset individually with `netlify env:unset <KEY> --site 76f606a3-8546-440f-8469-33a0236a8a23`. The site previously functioned with 10 vars before the repair; restoring that set reintroduces the build-time Supabase error.
- **Patch migration alone:** remove `patches/html-encoding-sniffer@6.0.0.patch`, delete its `patchedDependencies` entry from `pnpm-workspace.yaml`, and regenerate `pnpm-lock.yaml`.
